# rulevault

**给 AI 协作知识库的脚本强制闸门。** 规则不是写在文档里的建议，而是会自己检查的装置——开场有没有查库、写之前有没有取锁、收尾有没有结账，都有 Node 脚本拦着，漏了当场报错。

纯 Node ≥18 标准库：**零 npm 依赖、零外部服务、解压即用**。

## 两档，按需要选

| | [`lite/`](lite/) 轻量版 | [`framework/`](framework/) 框架版 |
|---|---|---|
| 文件数 | 7 个 | 59 个 |
| 上手 | 五分钟 | 半天通读 |
| 检查项 | 5 项体检（断链 / frontmatter / 空文件 / 临时残留 / 孤立页） | 7 项体检（含收尾证迹＋区域表一致性）+ 并发写锁 + 会话账本 + 提案待审 |
| 适合 | 想给 AI 一份能记住的库、不想要流程负担 | 多会话并行、要能追责、要把规则真正执行起来 |
| 起法 | `node scripts/check.mjs` | `node scripts/session-open.mjs` |

**从哪档开始**：先用 `lite/`，觉得"漏了没人发现"再升 `framework/`。两档的目录骨架一致、都不预设你的领域，升级是加东西，不是重来。

## 一、这是什么问题

跟 AI 聊久了会攒下大量内容，但 AI 没有跨会话记忆——**文件是唯一持久记忆**。于是自然长出一个"知识库"目录。可一旦库大到几十上百个文件，几件事就开始没人管：

- 该记的没记（讲过的概念、定过的判据，下次要重新问一遍）
- 该查的没查（库里有答案，AI 凭印象又编了一个）
- 写的时候互相踩（两个会话同时改同一个文件，一个的改动被另一个的提交带走）
- 说了改其实没改（"已更新"写在回复里，文件里没有）

**这个项目的主张：把这几件事变成脚本能检查的东西。** 规则一旦能被检查，就不会只停留在"记得要"。

## 二、机制长什么样

三层，都小而可读：

1. **规则层**（`AGENTS.md` / `使用手册.md`）：写在前面，AI 每次开场读它。
2. **检查层**（`scripts/`）：把规则里"可以机械判定"的部分抠出来，做成会 exit≠0 的命令。
3. **证据层**（`_AI/变更账本.md`）：每次写都留痕，事后能查"谁在什么时候改了什么、有没有结账"。

关键设计取舍：**每条规则都写明「为什么这样设计」**——不这样写，下一个人（包括三个月后的你）会以为是多余流程而删掉它。所以包里保留了大量"为什么不那样做"的论证，包括试过哪条路、为什么更糟。

## 三、目录

```
framework/          框架版（完整治理体系）
lite/               轻量版（7 文件冷启动）
```

两包各自都能独立解压使用；本仓库把它们放在一个地方，是为了让你先看轻的、再决定要不要重的。

## 四、快速开始

```bash
git clone https://github.com/<你的账号>/rulevault.git
cd rulevault/lite          # 或 framework
node scripts/check.mjs     # 轻量版；框架版用 node scripts/session-open.mjs
```

两包都**不需要** `npm install`——没有任何依赖。

## 五、它不做什么

- **不做向量检索**（那需要外部服务，与"零依赖"冲突）。检索靠关键词 `recall`，够用到库很大为止；升级路径写在包内。
- **不托管你的内容**。这是骨架：所有内容都是你自己填的 `{{}}` 占位。
- **不替你判断**。工具只负责"该做的做了没有"，不负责"这件事该不该做"。
