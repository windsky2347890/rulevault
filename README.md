# rulevault

这是一个给 AI 协作知识库用的脚本闸门项目。

跟 AI 聊久了库会越攒越大。没人管的话就开始出错——讲过的概念下次还要重新问、库里有答案 AI 凭印象又编了一个、两个会话同时改同一个文件互相踩、回复里写了"已更新"文件里没有。

rulevault 把这些变成脚本能检查的事。开场有没有查库、写之前有没有取锁、收尾有没有结账，漏了当场报错。纯 Node ≥18 标准库，零依赖，解压即用。

主要原则有四条：

1. 文件即记忆——AI 无跨会话记忆，文件是唯一持久记忆。重要信息必须落盘。
2. 简单可迁移——纯文本 Markdown + Git，不依赖专有软件，任何工具或 AI 都能接管。
3. 约定优先——文件名、格式、标题统一，多年后仍能快速定位。
4. 记录为了回顾——没回顾的记录只是仓库；写下来是为了将来能用、能查、能决策。

## 两档

lite（7 文件）适合一个人、一个 AI，不并发。framework（59 文件）适合多会话并行，或者你要能查出"上次谁改的、有没有收尾"。

拿不准先用 lite。两档目录骨架一样，framework 是往上加东西，不是重做。

```bash
git clone https://github.com/windsky2347890/rulevault.git
cd rulevault/lite
node scripts/check.mjs
```

不需要 npm install。

## 不做的

1. **向量检索**——要外部服务，跟零依赖冲突。库大了可以走本地嵌入 + 向量库（推荐 Ollama 配 LanceDB，不花 API 钱）。
2. **内容托管**——`{{}}` 占位的内容都是需要你自己填的。编辑用 Obsidian 这类 Markdown 笔记工具，版本用 Git，同步用 WebDAV 就够。
3. **替你判断**——只管该做的做了没有，其他时候只会做建议，决断还得你点头。
