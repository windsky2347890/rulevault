# 卡片体系（多工具适配：载体 ≠ 权威源）

> 问题：每个 AI 工具只认自己那个路径的开场文件（`AGENTS.md` / `CLAUDE.md` / 各家全局目录），于是同一条规则被抄到好几处——改一处忘三处。
> **解法一句话：把「载体」和「正文」分开。载体可以有很多个，正文永远只有一份。**

## 1. 两个角色

| 角色 | 是什么 | 谁维护 | 在哪 |
|---|---|---|---|
| **权威源**（唯一） | 规则的正文 | 人 + AI，按宪法与 [[_wiki/schema\|schema]] 走 | [[使用手册\|使用手册]]（宪法）、[[_wiki/schema\|schema]]、[[_wiki/开场导航\|开场导航]]、[[30-自我/速览\|速览]] |
| **载体**（可多份） | 各工具会自动读取的那个文件 | **生成**或薄手写 | 根 `AGENTS.md`、`CLAUDE.md`、`~/.config/<你的工具>/AGENTS.md`、`~/.config/<另一个工具>/AGENTS.md` … |

**判据：载体里出现"解释性段落"就是越界**（那是权威源的活）。载体只允许三类内容：
① **认人**（一两行身份，冷启动硬需求）② **触发**（"接任务 → 先查能力清单"这种短句）③ **指路**（去哪读正文）。

## 2. 载体分三型

| 型 | 适用 | 内容形态 | 例 |
|---|---|---|---|
| **A 工作区薄卡** | 有工作区路径、能自己读文件的 agent | 认人 + 触发词 + 指针 | 根 `AGENTS.md`、`CLAUDE.md`（桥） |
| **B 全局薄卡** | 工具会把某个用户级文件注入**所有**工作区 | 跨工作区不变的**最小自足集**（很短，因为别的目录读不到本库） | `~/.config/<你的工具>/AGENTS.md` |
| **C 自足卡** | 读不到文件（网页版 / 手机 / 别人电脑） | 完整可用的一页，可以长 | `50-工具/卡片/自足卡-粘贴给任意AI.md` |

区别的根源：A/B 靠"指针 + 工作区文件"生效，**C 必须自足**（没有文件可读）。

## 3. 新增一个 agent 怎么接（三步）

1. **查它认哪个路径**（AGENTS.md 标准？`CLAUDE.md`？自家全局目录？）。
2. **A 型 → 通常不用动**：多数工具共用根 `AGENTS.md`，只需把它的名字登记进 §4 表。
3. **B 型 → 加一个目标**：用 `--target "<标签>=<路径>"` 把它的全局卡路径加进命令，跑 `node scripts/sync-agent-cards.js --write --yes`（内容从 `50-工具/卡片/源-全局卡.md` 生成，永不失同步）。⚠️ `--write` 必须带 `--yes`，否则只打印将覆盖的路径、不写文件。
   **C 型 → 摘一份自足卡**：从宪法 + 开场导航摘，标日期。

> **扩展成本 = 加一个路径或一个文件，不动任何规则正文。** 这就是"适配很多 agent"的正确姿势。

## 4. 当前载体清册

| 载体 | 路径 | 型 | 谁读它 | 维护方式 |
|---|---|---|---|---|
| 工作区薄卡 | `AGENTS.md`（库根） | A | 支持 AGENTS.md 的各类工具 | 手写（全库唯一一份） |
| Claude 桥 | `CLAUDE.md`（库根） | A | Claude Code 类 | 手写桥（`@AGENTS.md` + 一句说明） |
| 工具①的全局卡（示例） | `~/.config/<工具①>/AGENTS.md` | B | 你在用的第一个工具（所有工作区） | **生成** |
| 工具②的全局卡（示例） | `~/.config/<工具②>/AGENTS.md` | B | 你在用的第二个工具（所有工作区） | **生成** |

## 5. 同步与检测（防漂移）

- B 型副本**由脚本生成**，源 = `50-工具/卡片/源-全局卡.md`：
  - `node scripts/sync-agent-cards.js`（默认 `--check`，只比对不写）
  - `node scripts/sync-agent-cards.js --write --yes`（写入所有目标；不带 `--yes` 只打印、不写）
- **收尾对账时跑一次 `--check`**：有差异 = 有人手改了载体 → 重跑 `--write --yes`（**副本是构建产物，不是第二事实源**）。
- 某工具改读新路径 → 回到 §3，只改 `--target` 参数。

## 6. 与「Prompt 分层治理」的关系

这个思路的判据是"一条规则一个权威源，同一条要求别换三种说法出现三遍"（相关笔记页在 `20-知识/nodes/`，本包不预置，需你自己建）。本页是它在**多工具现实**下的修正：

- 文章假设只有一个 agent（一个 `AGENTS.md`），所以"别复制"就够了；
- 现实是每个工具认不同文件，**副本不可避免**——那就让副本变成**生成的、可校验的构建产物**；
- **结论：允许重复内容，禁止手工重复。**
