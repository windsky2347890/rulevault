# 格式约定（专门法）

> 从 [[使用手册|宪法]] 拆出（专门法）。宪法只留钩子，细则在此。
>
> **本专门法规定「怎么组织」，不规定「你要记什么」。** 具体领域（日记／账目／健康／日程／课程／视频……）的格式**由你自己定**——本包**不预置任何领域的内容格式**，只给组织方法。

## 1. 组织方法

### 1.1 记录型页面 `10-记录/<你的领域>/`

- **放什么**：你的**领域**由你命名（账目／健康／日程／课程／观影……皆可）。本包只预置目录骨架，**内容与领域名都不预设**。
- **通用格式**：记录型页面建议按「时间 → 事实 → 变化」三段写；**具体字段由你定**，本包不替你规定表头。
- **别让空表变成装饰**：只有**真的用起来**的领域才建目录。建了不用、空着没人填，比不建更糟——它会让「有这一栏」看起来像「已覆盖」，而实际是空的。
- **触发点在哪**：由**你用的外部工具**决定（提醒／打卡／日程都在外部，本包不绑任何工具）；但**内容必须落盘到库里**——只有文件里的东西剪不掉。

### 1.2 知识 `20-知识/`

- 新素材先入 `00-收件箱/`，整理后转入 `20-知识/topics/`（主题）或 `20-知识/nodes/`（原子概念）。
- 原子概念放 `20-知识/nodes/`，一个概念一个文件，带 frontmatter。
- 原始资料（文章／视频逐字稿／扫描件）放 `20-知识/sources/`；**本包不预置这些文件，也不管它们的内部格式**。

### 1.3 目标与项目 `40-项目/`

- 每个项目一个目录；目标写清「领域 / 衡量标准 / 状态」。
- [[30-自我/速览|速览]]：长期愿景，自由格式。
- 想法、学习计划这类**还没成项目的东西**放在 `40-项目/` 下当普通项目管——**别另立一套目录**。

### 1.4 Wiki 维护（LLM Wiki）

- 工作区按 LLM Wiki 模式运行，AI 维护规则见 [[_wiki/schema|schema]]。
- 每次处理新素材后，更新 [[_wiki/index|index]] 和 [[_wiki/log|log]]。
- Obsidian 首页是 [[_wiki/Home|Home]]，各领域入口见 `_wiki/MOC-<领域>.md`（**需你自建**，本包未预置）。

## 2. 通用对话指令（自然语言即可，以下只是示例）

- 落盘："把这段记到〈你的领域〉里" / "写一条〈你定的领域〉记录"
- 查询："查〈领域〉里〈某项〉的情况"
- 入库："入库这篇文章" / "帮我 Lint 一下知识库" / "打开首页"
- 回顾："回顾〈你定的周期〉"（**回顾流程由你定**，本包不预设周／月／年的具体清单）

> ⚠️ **本包不预设领域**，所以也不预设「记账怎么记」「日记怎么写」「视频怎么转」。这些**是你的内容**，不是框架的一部分。
