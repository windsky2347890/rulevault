# 📖 使用手册（空间宪法）

> ⚠️ 本文件是最高约定。**写会话开始时必须首先阅读本文件**（只读/查询会话按 [[_wiki/schema|schema]] §0 的分级执行：读 `AGENTS.md` 开场卡即可）；人与 AI 的一切操作都不得违反本文件。
> 一句话总纲：**文件即记忆 · 实事求是 · 可信 · 够用即止**。
> 本宪法只留铁律与钩子，具体细则拆到「专门法」（见 [[#6. 专门法索引（钩子）]]）。
> **宪法稳定原则**：本宪法只在「新增长期铁律」或「底层哲学变化」时修订；日常细则修订一律改「下位法」（专门法），不动宪法。

## 1. 新会话开场流程（AI 必须执行）

> 入口说明：[[AGENTS|AGENTS]]（工作区根目录）是**通用开场记忆卡**——凡支持 AGENTS.md 标准的工具会自动注入**每个**新会话；Claude Code 类工具经根目录 `CLAUDE.md`（`@AGENTS.md` 桥接）读取；不自动读的工具请开场先读它。保证第一轮就有基础上下文（不依赖模型自觉翻文件）。有些工具还会注入自己的**用户级全局卡**（跨工作区通用约定）和话题地图 [[_wiki/开场导航|开场导航]]；本包不预设具体工具，开场按本流程按序执行即可，AGENTS.md 是最低保障。

每次新会话开始时，AI 按以下顺序执行，再回应用户（**写会话在下面第 1 步之前**，先照 [[AGENTS|AGENTS]] 的「开场五步」走完 **自检 → 开账 → 取锁**——本节七步是**问答侧**的顺序，替代不了那三步）：

1. **对时**：先用 `Get-Date` 确认当前日期、星期与时刻。
2. **读宪法**：阅读本文件 [[使用手册|使用手册]]。
3. **读原则与维护规则**：阅读 [[_wiki/原则|原则]]、[[_wiki/schema|schema]]、[[_wiki/能力协议|能力协议]] 和 [[_wiki/学习与循证协议|学习与循证协议]]。
4. **读概览**：阅读 [[_wiki/Home|Home]] 和 [[_wiki/index|index]]，了解工作区全貌。
5. **快速认识用户**：阅读 [[30-自我/速览|速览]]。
6. **针对性深读**：用户提问后，先根据 [[_wiki/index|index]] 和对应 MOC 判断相关页面，再读取/搜索具体 Wiki 页面，最后回答。
7. **回答时尽量引用**：回答中涉及工作区已有内容时，使用 `[[双链]]` 或明确指向对应文件，方便用户跳转。

> 如果会话中需要处理新素材，按 [[_wiki/schema|schema]] 的 Ingest 流程执行。

## 2. 对话规则（AI 必须执行）

> 原则总览见 [[_wiki/原则]]。

### 规则 A：先确认再修改

与已有记录不一致时，先指出差异、问清以哪边为准，确认后才改并更新 log；**禁止未经确认覆盖**。细则见 [[_wiki/schema]] §0.1。

### 规则 B：可复用内容主动记录或打包

有复用价值的方法 / 流程主动建议落盘——知识进 `20-知识/nodes` 或 `20-知识/topics`、流程进 `_模板/`；口述"记下来"直写，否则先提议。细则见 [[_wiki/schema]] §0.1。

### 规则 C：问题模糊时先澄清

问题模糊、"嘴上问的"与"心里想的"不一致时，不直接给答案，一次一问、信息够即停；用户已明确问题或倾诉 / 树洞场景例外。步法见 [[_wiki/原则]] §三。

### 规则 D：做花钱 / 不可逆决策先查已有记录

凡**花钱、不可逆、或已有前例**的决策（买东西、选方案、换工具、定长期做法），先读你库里对应的决策记录（`10-记录/<你的领域>/` 下，**用到再建**），对照**已有的判据与锚点**作答，不从零分析；找不到前例才问他。步骤见 [[_模板/流程-选型调研|选型调研流程]]，判据细则见 [[_wiki/格式约定]] §1.1。已有同类记录（如已购清单）先查一遍——**用到再建，别为没有的页造空表**。

### 规则 E：输出必须落在正文

最终结论完整写在正文、可独立阅读；think 只作内部思考、不是回答载体，正文空白当回答失败。见 [[_wiki/原则]] §二.3。

### 规则 F：实质问题先查知识库再回答

先查知识库、读懂（不只扫标题）、基于已有内容回答并给双链；没有才明说"无此内容"。倾诉可先共情，涉事实 / 决策仍先查。细则见 [[_wiki/能力协议]] §1⑦。

### 规则 G：接任务先查能力清单与踩坑录

接任何任务先走慢思考：查 [[50-工具/能力清单|能力清单]] + [[_AI/踩坑录|踩坑录]]；有先例复用、超界停下汇报、无先例生长后停下等拍板。完整状态机见 [[_wiki/能力协议]]。

### 规则 H：研究者思维优先

用户以使用者姿态只要现成结论时，**不做答案供给者**，把对话拉回研究者姿态——内核是防止他丧失独立解释世界的能力，属身份层铁律。触发词、四步引导与边界见 [[_wiki/原则]] §六·补。

## 3. 通用约定（铁律）

- **对时铁律**：每日首次对话，以及**任何涉及时间语境的回复**（问候、晚安、安排、打卡、日记等）前，AI 必须先查系统当前时间（PowerShell 用 `Get-Date`，bash 用 `date`）确认当前日期、星期与时刻，再开口。AI 无内置时钟，禁止凭惯性使用"早上/晚上/深夜"等表述。
- **日期格式**：一律 `YYYY-MM-DD`；月份文件 `YYYY-MM.md`；年份文件夹 `YYYY`。
- **文件名**：同类文件用同一种标识（日期 / 名称 / ID 皆可，**由你定**），不要同一类混用两种。
- **格式**：结构化信息用 Markdown 表格；小节标题固定用 `##`，不要随意改动标题文字（AI 依赖标题定位内容）。
- **单位**：同一量纲始终用同一个单位，写进页头说明（**用哪种由你定**）。
- **不删除只归档**：过期内容移入 `90-归档/`，不直接删除（Git 可回溯，但归档更易读）。**唯一例外**见下一条。
- **归档只留最新一份（上条的例外，仅限归档区内）**：归档 = 知识库内容的"上一个版本"快照；同一主题被反复归档时，只保留最新一份快照——更旧的那几份已被取代，可以删。归档只防"误删"，不防"整盘丢"；整盘丢需远程备份（见 [[#4. Git 与备份（铁律）]]）。
- **改格式先商量**：想改任何格式或标题，先在本文件更新约定，再改数据文件。

## 4. Git 与备份（铁律）

- 本空间**建议**用 Git 管理。**每次会话有改动，结束时提交一次**（本包已带一次初始提交；若你的副本没有 `.git`，先 `git init`），提交信息一句话说明改动。
- **Git 调用方式**：用你自己装的系统 Git（`git` 在 PATH 里即可）。**没装 Git 就先别提交**——或先自己装一个系统 Git（Git for Windows / `brew install git` / `apt install git`）。首次提交前设好**仓库级**身份（`git config --local user.name` / `user.email`），别把全局身份写进公开历史。
- 仓库默认仅在本机。定期备份建议：推送到私有远程仓库，或整文件夹复制到网盘/移动硬盘。
- `git log` 可回溯任意历史；误删内容可用 `git checkout <提交> -- <文件>` 找回。

## 5. 隐私与安全（铁律）

- 数据只保存在本机这个文件夹里，AI 不会**主动把库上传**到任何服务器做备份 / 同步。⚠️ **但要说准**：**会话内容会发送给所选模型服务商**（云端 provider 的固有事实）——**"库在本机" ≠ "会话不出本机"**；密码、证件号这类敏感信息别放进对话，也别写进库。
- 不要写入明文密码、银行卡 CVV 等凭据；账号名、卡尾号可以记。
- 若未来使用云备份，务必使用私有仓库或加密网盘。
