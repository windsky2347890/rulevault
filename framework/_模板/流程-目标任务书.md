# 流程：目标任务书（长任务开工前）

> **适用**：**命中任务书触发判据**的长任务（≥2 个独立交付物 / 需设计决策 / 改动 ≥3 文件或结构性重写 / 改解释权或影响历史数据 / 用户明确要求；判据见 [[AGENTS|AGENTS]]）——如一整本资料的整理、一次大重构、多 agent 并行。**纯问答 / 单条改动不用**。
> **方法论**：指挥官意图——只锁「为什么干」和「干完什么样」，手段允许执行者随机应变；**Harness 比 Goal 重要**——先想达成目标最偷懒的路径，逐条堵死，剩下的才是目标。
> **去重**：日常对话的目标澄清走宪法规则 C（苏格拉底式），本流程只在长任务开工时用，两套不并用。

## 一、开工前三步

1. **先调研后提问**：自己能查的一律不问（库内 read/grep、实测命令、来源核验）；查不到的标「假设，未验证」。
2. **一轮 ≤5 问**：只问查不到且会改变任务书的（方向取舍 / 验收裁量 / 风险偏好 / 时间盒），每问给 2–4 个选项 + 推荐；替用户拍的板单列「我替用户拍的板」一节摆明面——沉默代拍是越权，写明是尽职。
   - 🔴 **选项标签的两条纪律 ＋ 一条边界（源自一次口径误读的实测复盘）**：
     - **① 报警器（结构判据）**：**"多个有区别的东西被装进同一个选项 / 标签里"＝必须警惕**。判据＝**这个标签能不能唯一对应到"一个具体动作"？对不上就拆成互斥项**。写选项时先自检「**我这一栏里装了几样东西**」（装了两样以上就拆）。高危词只是附注：绘图 / 设计 / 学习 / 整理 / 记录 / 研究。
     - **② 标签纪律**：**标签里不许出现 AI 自造的措辞**——自问「**这个括号里的词，是他的原话，还是我的判断？**」是我判断的就**别进标签**（同族错误：把"推荐"标在 AI 偏好的那项上 ＝ 用提问的形式做决定）。
     - **⚠️ ③ 边界：别执行过头（已与用户确认）**：**颗粒度要匹配决策分辨率，不是越细越好**——判据＝「**这一刀会不会改变结论**」：拆开后若两支给出**同样的选择**，就不必拆。**报警器管"该拆的没拆"，边界管"不该拆的乱拆"，两者必须成对出现**，否则本规则会被执行成"什么都拆"。（原理层见 [[20-知识/topics/AI原理笔记|原理笔记]]——「颗粒度」是你要用的条目名，非包内已有条目）
3. **分型**：动笔前能写出验收命令的是**执行型**，全套照走；要答案本身的（调研 / 选型 / 该不该做）是**探索型**——不设凑数硬指标，产出 = 报告 + 证据。

## 二、任务书七问结构

| 问 | 内容 | 关键 |
|---|---|---|
| Why 目的 | 为什么干这趟 | 执行者在岔路口的判断依据 |
| Done 完成态 | 回港时甲板上有什么 | 具体到一眼能判 |
| Proof 证据 | 谁来清点、怎么算数 | 验收命令 / 清单；**执行者不能自己批卷** |
| Anti 反作弊 | 最偷懒的达成路径逐条堵死 | 基线不可退 + 点名禁止具体姿势 |
| Bounds 边界 | 只许走哪几条航线 | 范围白名单 / 时间盒（如"第 N 天还没成就掉头"） |
| Trade 取舍 | 冲突时保哪个 | 提前定优先级，不许执行者猜 |
| Unknown 未知 | 海图空白怎么办 | 记下来绕过去继续走，不硬闯也不抛锚 |

## 三、防五种死法（写书时自检）

1. **作弊达标**：指标一样但事没干（为过检查而删检查、造假数据凑数）→ 基线不可退 + 点名禁止具体姿势 + 抽查项不进书。
2. **幻觉命令**：平静地编造命令再甩锅环境 → 书中每条命令开工前亲手跑过，跑不到就写成任务 0 让执行者先查实。
3. **失忆**：跨会话重做 / 丢进度 → 进度写 PROGRESS 文件，接手先读它；开工先交 ≤10 行回执（理解的目标 / 顺序 / 最大风险）。
4. **一条道走到黑**：前提错了也硬跑 → 任务 0 先核前提，量出的数字对不上就停；同一验收连败 3 次换项；结果比基线差就回滚如实报——「没做成但说清了」合格，「做了但更糟」不合格。
5. **静默事故**：坏了没人知道 → 反向验证——亲手制造一次失败，证明报警器会响，贴输出。

## 四、写书纪律

- **法与情报分家**：「不许」是法（违反即不合格，逐条溯源到实测或用户裁决）；「建议」是情报（执行者可走更好的路，但要记录理由）。
- **事实全部核验**：执行者把书当唯一真理、中途无人可问——写错的事实 100% 被执行（schema 规则 C 的极端版）。
- **全文不许「来找我」**；库内已有的约定 / 格式文件直接写路径引用，不散文复述。
- **一页能读完**：过程噪音（调研表、分析过程）不进书；压不进说明活太大，拆。
- **验收分明暗**：明卷（验收命令）进书让执行者自盯；暗卷（2–3 条执行者看不见的抽查）留在会话侧。
- **多 agent 并行**：每份书带同一段「全局」（整体干什么、谁管哪段、接缝在哪）；地界错开；共享写入点指定唯一归属。

## 五、收尾验收

执行者交卷后：复跑明卷 + 暗卷 → **≤5 行人话报告**（过没过 / 干成了什么 / 遗留问题 / 下一步）。任务书原件存任务目录（`40-项目/` 或对应位置），[[_wiki/log|log]] 记一条。

### 产出闭环（执行兜底）

> 指针（"长任务先走目标任务书"）已由 [[AGENTS|AGENTS]] 的「任务书触发判据」/ [[_wiki/能力协议|能力协议]] §5 承担；本流程补的是**"走了没走"的可查尾巴**——执行靠产出证明，不靠模型自觉。

- 走完目标七问，**目标任务书必须落盘**：写入 `40-项目/<项目名>/目标任务书.md`。
- 会话收尾 log 附证迹：`任务书:✓ 已落 <项目名>/目标任务书.md`。
- **缺产出 = 未走完**：schema §8 检修把"长任务无对应任务书 / log 缺证迹"记违规回流，下次写会话补。
- 与 schema §8「收尾证迹」同构：**执行者是否真跑，用"该出的任务书 / 证迹在不在"来查**。
