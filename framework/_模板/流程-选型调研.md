# 流程 · 选型调研（通用骨架 · 含商品口径）

> **触发词**：「帮我选 X」「X 该怎么挑」「调研一下 X」「哪个更适合我」
> **一句话**：**先验需求、再定判据、拉候选、出榜**——不是"找最便宜/最有名的那个"。
> **这是骨架不是现场**：下面每一节都只给**方法和槽位**，`{{}}` 与示例形状要换成你自己领域的内容。别把某个具体行业的标准、阈值、话术搬进来——那是你的工作现场，不是模板该有的东西。

---

## 〇、前置（30 秒）

1. 有没有**同类记录**已经写过？先查，避免重复调研（你自己的记录入口：`{{记录位置}}`）。
2. 有没有**已经能用的替代品**？先确认不是在重复解决同一个需求。
3. 有没有**你自己的标准页**？有就先读它（权重与门槛可能已更新）；没有就边调研边建。

## 一、六步（顺序不可乱）

> **总顺序**：第一性需求 → 可验证判据 → 候选 → **主榜** → （可选）叠加非方案因素 → 落盘。
> **关键纪律：定判据之前不许看候选，出主榜之前不许掺非方案因素**——先把"什么算好"定死，再去挑；否则判据会跟着看到的候选漂。

### 第 1 步 · 第一性需求（**不做这步，后面全白做**）

- **往上追一层，别停在物品/选项名上**：不是"要买台灯"，是"晚上看书不刺眼"；不是"要选某门课"，是"能独立做出某类分析"。
- 让他用**一句话**说清：**用途**、**频率**、**硬约束**（预算 / 时间 / 环境 / 身体条件 / 必须兼容的东西）。
- 逐条问：**"现在多久用一次？未来是增还是减？"**；**信息不足就先问，绝不替他假设**（他给得越少越要问）。
- 列 3–5 条**真实需求**，逐条验真；**已被现有条件覆盖的当场划掉**（别为"无证据的溢价"买单）。
- 产出：**"我要的到底是什么"一句 + 保留的需求 + 被划掉的伪需求**。

- 🔴 **同一步·钉死边界**：**第 1 步必须写死本次调研的范围边界**，一句话。
  - 例：「仅 A 类，排除 B / C / D」——**技术路线/品类不同，榜不可混**。
  - **为什么写死**：把相邻品类混进同一张榜，**混线 ⇒ 排名失效**。
  - 判据：**榜里出现任何不属于该范围的条目即违规**；跨范围只允许出现在"另案调研"的一句话备注里。

- 🔴 **同一步·场景词必须先问出「操作定义」**：**凡要拿来当判据的词，不得按 AI 自己的常识建模**，必须在第 1 步锁死它**对应什么具体动作**。
  - 完整判据（报警器 ＝「标签里装了几样东西」／标签纪律 ＝ 不许把 AI 先验写进选项／颗粒度边界）见 [[_模板/流程-目标任务书|目标任务书流程]] §一「开工前三步」——**那里是唯一权威源，本页不重复**。
  - 本步只记这一条硬要求：**答不出具体动作 ＝ 没钉死；钉死前不许定判据**（第 2 步不许开工）。

### 第 2 步 · 定可验证判据

- 把需求翻译成**可验证的数字或可判的条件**。
  - 好的判据：能查、能测、能对；坏的判据：形容词（"好的""稳定的""性价比高的"）。
- **查明对口的规范/标准**（该领域有强制标准或权威口径的，一定先查；**别照抄任何示例，示例只是形状**）：
  - 记下**标准号/口径出处**，判据是**标的与实物是否对得上**。
- **判据分两档**：**硬指标**（不满足直接出局）／**加权项**（都满足时用来排序）。权重写进你自己的标准页，模板不预设分值。

### 第 3 步 · 拉候选——**先定口径，再定档位**

- 数量：**3 个左右**（复杂决策可到 3–6）。
- ⚠️ **先定口径**：对象**有价格可比**（商品 / 服务 / 订阅）还是**没有**（技术栈 / 方案 / 学校 / 组织）？两条路分开走：
  - **有价格 → 价格锚点法**：覆盖两种档位（"平台期"思路的落地）——
    1. **锚点**：满足全部硬指标的**最低档**＝平台期，成本摊到使用期最低；
    2. **加一点换质变**：比锚点高一档，但多花的必须买到对**核心需求**的**明确质变**（写清"多花 X 买到什么"，买不到就不列）。
  - **没有价格 → 硬指标档位法**：覆盖**最低满足档** ＋ **高一档**（同样要写清"高在哪、是否值"），**不要硬造价格锚点**——判据换成硬指标与验证项。
- 每个候选记：**名称 / 关键规格 / 价格或成本（有则记） / 来源 / 日期**。
- ⚠️ **实时数据常常抓不到**（页面靠 JS 渲染/反爬/需登录）→ 用**可查的历史值或零散值**，**逐条标来源与日期**，写明"是量级不是今日实价"。

### 第 4 步 · **主榜（只看方案本身）**

按你自己的标准页填：**需求命中 / 硬指标 / 档位 / 总成本 / 验证项 / 排除项**。

- 排序只依据**方案本身**：对核心需求的满足度 + 摊到使用期的成本。
- **成本口径**（对象有价格时）：摊成**单位成本**（每次/每年/每单位量），不要用"单件多少钱"比——同标注下实际分量可能差一倍；**没有价格的，这条跳过**。
- 明确标出：**锚点首选 / 加钱质变首选 / 出局项（含出局的证据层理由）**；**无价格对象**改写为「最低档首选 / 高一档首选 / 出局项」。
- 这一步结束时，主榜推荐已经成立——**即使不查非方案因素也能决定**。

### 第 5 步 · （可选）叠加非方案因素

> **默认可以跳过**——主榜成立就已经能定了。只有当你确实在意责任/合规/可持续/长期关系这类因素，才另开一榜；**并列展示，不推翻主榜**。

四条通用判据（具体查什么、去哪查，写进你自己的标准页）：

1. **信息可查门槛**：主体信息都查不全的候选**不进榜**——不是判它违规，是拒绝在信息黑箱上投票。
2. **红线门槛（一票否决）**：你自己列几条不可接受的事；命中即出局，理由单列。
3. **加权打分**：权重表写在标准页，给最在意的项最高权重；本模板不预设分值。
4. **覆盖率随分数一起报**：查不到的项如实标「不可查」，覆盖率低的分数不可信。

**证据分级（先分级再判断）**：一手公示/官方文件 ＞ 专业评测 ＞ 当事人自述（**≥3 条独立来源才算信号**）＞ 营销号与聚合页（只当线索）。**互相抄袭不算多源**。

⚠️ **机器抓不到的**（需登录的社区、要验证码的公示）：由你去看 + 截图/链接给 AI，AI 只负责分级、交叉、落盘。

### 第 6 步 · 落盘

- 结论写回你的**记录页/总表**（`{{你的记录位置}}`）：选项 / 理由 / 判据 / 状态 / 下一步
- 值得单开的（大件、多轮决策）→ 建独立决策页
- 会话收尾写 `_AI/会话日志.md`

## 二、输出模板（严格按"先主榜、后综合"两张榜）

```
对象：<X>　｜　数据截止：YYYY-MM-DD　｜　对口标准/口径：<标准号 / 出处>
范围口径：<仅 XX，排除 YY/ZZ>　｜　本榜排序口径：<单位成本 / 体验 / 综合（权重）>　← 必填

【第1步·第一性需求】我要的到底是什么（往上一层）/ 用途·频率·硬约束 / 划掉的伪需求
【第2步·可验证判据】硬指标清单 + 加权项与权重
【第3步·候选】有价格：锚点 ×1~2 ＋ 加钱质变 ×1（标注"多花X买到什么"）｜无价格：最低满足档 ×1 ＋ 高一档 ×1（标注"高在哪、值不值"）

【主榜（只看方案本身）】
| 候选 | 需求命中 | 硬指标 | 规格 | 价格/成本(来源+日期，有则记) | 折算单位成本（有价格时） | 角色(锚点/加钱/出局｜最低档/高一档/出局) |
→ 主榜推荐（此榜独立成立）

【（可选）综合榜（主榜存活候选）】
| 候选 | 信息可查(≥N/M) | 红线 | 因素1 | 因素2 | 因素3 | 加权分 | 覆盖率 | 依据链接 |
→ 出局：红线 / 不透明（各列理由）
【结论】<主榜首选> × <综合后是否换人> ＋ 一句话理由 ＋ **未决项/缺口（含待人工查的部分）**
```

## 三、已知缺口（诚实声明，禁止编造）

- **实时数据**：常拿不到 → 用可查的历史值/零散值并标注
- **不公开的信息**（内部数据、非公示的评级、第三方报告）→ 查不到就标 🟡，**绝不默认合规**
- **主体 ≠ 品牌/平台**：问题常出现在实际承担方
- → 查不到就标"不可查"，**别用猜测填**

## 四、纪律

1. **先问需求，再动手**（第 1 步不做完不出榜）
2. **每个数字带来源与日期**；估算的标"估"
3. **不替用户做决定**——给两榜 + 推荐 + 缺口，让他拍板
4. **工具挂了要说**（搜索额度耗尽/接口不可用时，如实告诉他，不能假装调研过）
