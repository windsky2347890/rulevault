# rulevault —— 给 AI 协作知识库的脚本强制闸门

> **规则不是建议，是会自己检查的装置**：开场有没有查库、写之前有没有取锁、收尾有没有结账——都有脚本拦着，漏了当场报错。
> **零依赖、零服务、解压即用**：纯 Node ≥18 标准库，不装 npm 包、不要 MCP 网关、不要向量服务。
> **双档分层**：本包是**完整治理体系**；同仓库的 [`../lite/`](../lite/) 是 7 文件、五分钟冷启动的轻量档——先用轻的，觉得不够再升上来。
> 注：此 `../lite/` 指针在 framework 独立解压时不存在（两档各自可单独解压使用）。
>
> 这是一套从个人知识库里抽出来的**框架**：规则 + 脚本 + 目录结构。
> **内容已经全部清空**——文件里凡是 `{{}}` 都是**要你自己填**的地方。

---

## 一、三步上手

**第 1 步：填「认人」**（最重要）

打开 `AGENTS.md`，把「认人」那一节的 `{{}}` 换成你自己。这是 AI 每次开新会话认识你的唯一入口——不填，它每次都从零问起。

**第 2 步：跑一次体检**

在本目录执行：

```
node scripts/lint-wiki.js
```

预期输出末尾是「✅ 0 阻断，提醒项归零」。

**第 3 步：对 AI 说第一句话**

随便问点什么。它应该**先读 `_wiki/开场导航.md`**（话题地图），再按图去找文件——而不是凭空回答。

## 二、要填的地方（按重要性排序）

| 位置 | 填什么 | 不填会怎样 |
|---|---|---|
| `AGENTS.md` →「认人」 | 称呼 / 身份 / 长期目标 / AI 的角色 | AI 每次从零问你 |
| `30-自我/速览.md` | 上面那节的精简版（≤10 行，给 AI 看的） | AI 缺少"你是谁"的摘要 |
| `_wiki/开场导航.md` | 你的**话题 → 文件**地图 | AI 不知道"问 X 该读哪个文件" |
| `50-工具/能力清单.md` | 你有哪些现成命令 / 工具 | AI 会重复造轮子 |
| `_模板/写作方法.md` | 你写东西的规矩（不要什么、动笔前先问什么） | AI 写的稿子你会想删掉重写 |
| 标了 `待建` 的空壳 | **用到再填**，不必一次填完 | 相关那条规则落不了地 |

**找出所有占位符**：用编辑器全局搜索 `{{`，或命令行：

```
# Windows
findstr /s /c:"{{" *.md
# macOS / Linux / Git Bash
grep -rn "{{" --include="*.md" .
```

## 四、脚本（`scripts/`）

| 命令 | 干什么 |
|---|---|
| `node scripts/session-open.mjs` | 开场自检：账本 / 锁 / 待审 / git 状态一眼看完 |
| `node scripts/session-ledger.mjs --check` | 查有没有"上次没做完、没结账"的会话 |
| `node scripts/session-ledger.mjs --start "做什么"` | 开账 |
| `node scripts/session-ledger.mjs --end "锚点片段"` | 结账 |
| `node scripts/write-lock.mjs add --region <区域> --files <文件> --note "在做什么"` | 取写锁（多会话并发时防互相覆盖） |
| `node scripts/write-lock.mjs check --region … --ignore "你取锁时的 note 片段"` | 查冲突 |
| `node scripts/write-lock.mjs remove "匹配串"` | 释放锁 |
| `node scripts/recall.mjs "关键词"` | 全库检索兜底（话题地图没覆盖时用） |
| `node scripts/lint-wiki.js` | 全库体检七项：断链 / frontmatter / 空文件 / 临时残留 / 孤立页 / 收尾证迹 / 区域表与代码一致（**断链与缺收尾证迹＝阻断**，其余＝提醒） |
| `node scripts/sync-agent-cards.js --check` | 检查各 AI 工具的全局卡与源卡是否一致（**只有 `--write --yes` 才会写**） |
| `node scripts/sync-must-keep.mjs --write` | 改了宪法后重新生成 `_wiki/_每轮必守.md`（`--check` 只比对、不一致即报） |
| `node scripts/release-check.mjs [目录]` | 发布前第一道闸门：形状扫描（手机号/邮箱/UUID/长 hex/用户目录路径）＋**本机身份**（读到真值就查真值，含 8.3 短名变体） |

> ⚠️ `sync-agent-cards.js --write` 会**覆盖**目标全局卡（路径可配）。**`--write` 必须带 `--yes`**——不带时只打印将覆盖的路径并退出、不写文件；带 `--yes` 时写前自动备份。第一次用先跑 `--check` 看差异。

> ⚠️ `write-lock.mjs add` 有**四道前置闸门**：① 路径形状（`--files` 不能写目录/通配符）② 12 小时内的开场戳（先跑 `session-open`）③ 账本里的「进行中」锚（先 `session-ledger --start`）④ 上次收尾的未结清项。漏了任一步会被拦下并给出具体缺哪一项——**不是报错，是协议没走完**。

## 五、脱敏说明（关于这份包是怎么来的）

抽取这份框架时做了这些处理：

- **删除了原库的全部内容**（日记 / 财务 / 人物 / 项目 / 知识页），只保留**规则、脚本、目录骨架**
- 规则正文里的**署名替换**成了「用户」
- **删除了**原库的私人路径、私人项目页、私人提案链接与内部编号
- **已去掉规则正文中的立法日期戳与开发过程叙事**——只保留「为什么这样设计」的部分（那是给你用的，不是给你看的历史）。**脚本注释里仍保留了部分设计沿革**（用于解释为什么这样写，不是维护日志）
- **不含原库的 `.git` 历史**（原库的 git 历史里有隐私数据，故整段历史不带）；本包自带的 `.git` 只有**一次初始提交**，没有历史包袱

**脱敏进度（如实）**：形状扫描 0 命中＋阳性对照报红已完成；**干净上下文逐文件通读**按 `DESIGN.md` 由独立审查者逐文件复核，**记录表留在包外**（含审查引文，不随包分发）。按 `DESIGN.md`，两道齐才算发布通过。

## 六、排错

> **首次解压（无 `.git`）**：跑 `session-open.mjs` 会打一条 `fatal: not a git repository` 且 rc=2 —— 这是**预期行为**（脚本头已声明），不是故障；等 `git init` 后再跑即可。`session-ledger.mjs` 在无 git 时会降级（不报 git 状态），不阻塞。

**`lint-wiki.js` 报断链**
正常的空壳不会被算作断链。如果报了，说明有页面链接指向不存在的文件——按提示补空壳或删链接即可。

**`session-ledger.mjs` 报 "git" 相关错误**
它用 `git hash-object` 算文件指纹。你的目录**不是 git 仓库**（例如解压后没 `git init`），所以某些功能会降级。想用完整功能：

```
git init
git add AGENTS.md README.md 使用手册.md   # 逐条点名你要提交的文件
git commit -m "init"
```

> ⚠️ 不要用 `git add -A` / `git add .`——会把运行时状态文件一起收进去。本包 `.gitignore` 已排除 `_AI/.写锁`、`_AI/.开场证迹` 等，但仍建议逐条点名、提交前 `git status` 看一眼。

**`write-lock.mjs` 说"区域必须是 …"**
区域只允许这几个值：`_wiki` / `knowledge` / `record` / `project` / `tool` / `scripts` / `meta` / `archive`。权威表在 `scripts/lib/regions.mjs`（改了要同步 `_wiki/schema.md` §0.2 那张表）。

**AI 不读我的文件 / 每次都重新问**
八成是「认人」没填，或它没读 `AGENTS.md`。直接把 `AGENTS.md` 内容贴给它一次，或确认你的 AI 工具会读根目录的 `AGENTS.md`。

## 九、怎么按你自己的领域扩展

这套框架**不预设你干什么**——它只规定「东西放哪、规则怎么改、怎么防自己骗自己」。你的领域（工作、研究、爱好、副业……）要长出具体页面，按这三步加，**不用改框架本身**：

1. **加领域页面** → 在对应目录建文件（`10-记录/` 记事实、`20-知识/` 攒知识、`40-项目/` 放进行中的事）。目录**用到再建**，本包不预置。
2. **加流程模板** → 复制 `_模板/流程模板.md` 改名（`_模板/流程-你的名字.md`），按自己的流程填。**别在框架的模板里塞你的场景**——模板是给别人抄的骨架，不是你的工作现场。
3. **加自己的话题地图** → 往 `_wiki/开场导航.md` 的「你自己的表」加行；也把示例表里跟你无关的删掉。

改规则（宪法 / schema / `AGENTS.md`）是另一回事：**先立提案、过了再改**——见 `_AI/待审/README.md`。

> 三条扩展原则：**① 加内容不用改框架；② 改规则要过闸；③ 你的领域内容不进框架模板。**
