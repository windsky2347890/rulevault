# 设计说明 · 发布判据

> 这一页只回答一个问题：**什么时候可以说「可以发布」**。

## 发布 ＝ 两道，缺一不可

1. **形状扫描**：`node scripts/release-check.mjs [目标目录]`
   - 扫手机号／邮箱／UUID／长 hex 标识符／用户目录路径；外链单列出来供人工复核，不自动判红。
   - **本机身份检查**（🔴 **一次评审实测漏网**）：形状规则只覆盖完整用户目录路径，裸用户名漏网 ⇒ 脚本读到 `os.userInfo().username` 等真值后直接按词匹配，四态变体（原样／全小写／全大写／8.3 短名）都查。含**去重**。
   - **必须配阳性对照**：往临时副本注入①假手机号 ②**裸用户名** ③**8.3 短名** ④完整用户目录路径 ⑤假用户名（如 `TestUser2024`），重跑**必须报红（exit 1）**，干净副本必须 rc=0。不报红 ⇒ 扫描器没在干活，这道闸不算数。白名单不得放行该样本。
   - 🔴 **闸门改了，判据必须跟着改**——形状规则换成本机真值检查后，如果文档里的规则清单还只列旧形状、阳性对照还不验新变体，「闸门存在但判据不要求验它」＝同一次漏网的病理。**每次给闸门加能力，同步改本节与 README 脚本清单。**
2. **干净上下文逐文件通读**：另起一个**不继承本次会话记忆**的审查者，逐文件读全部发布态文本文件（md ＋ 脚本 ＋ 配置），产出通读记录表——每行写「这页在教什么／这文件干什么」，md／脚本／配置三段小计、合计＝文件数；5 处高敏页留「原文摘句 → 判定」。

**两道都过才算发布通过。** 只有第 1 道 0 命中，结论只能写「形状层干净」，不能写「可以发布」。

> 为什么还要第二双眼睛：形状扫描抓不到**举例式泄露**——专业公式、真实页名、亲属称呼、某人的原话，形状上完全干净，却是能拼出一个人画像的内容。

## 判据是怎么来的（别退回老办法）

- 早先按「期望清单」核对，清单外的东西（id、hex、UUID、手机号）**静默漏过** ⇒ 改成按形状扫，不按清单扫。
- 用文本工具扫中文要注意编码：编码猜错会**假报干净** ⇒ 一律用 Node 以 UTF-8 逐字节读。
- 扫描器自己输出 0 不能当证据 ⇒ 必须能被注入样本打红。
- 脚本注释是实测过的泄露向量 ⇒ 通读记录表**不得排除脚本行**。

## 轻量版借用

同仓库的轻量档 [`../lite/`](../lite/) 不必自带发布检查脚本：**同仓库布局下**从本目录跑 `node scripts/release-check.mjs ../lite`；通读记录表照本节覆盖它的全部文本文件。**目标目录是显式参数**，脚本不会按自身位置猜库根。

## 发布流程（顺序写死）

1. `node scripts/lint-wiki.js` ⇒ 0 阻断且提醒归零
2. 形状扫描 0 命中 ＋ 阳性对照报红
3. 通读记录表：覆盖全、无遗留发现
4. `git status` 干净、提交身份为仓库级占位（不动 `--global`）
5. **push 由人亲手点** —— 本包不自动推送
